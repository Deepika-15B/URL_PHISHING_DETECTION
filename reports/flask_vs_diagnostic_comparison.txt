STEP 9 -- ROOT CAUSE EXPLANATION
================================================================================

THE BROWSER IS CONNECTED TO A COMPLETELY DIFFERENT UI THAN THE FLASK SERVER UI.

Evidence chain:

  1. Flask backend (port 5000) was built with templates/index.html
     This UI correctly calls /predict, renders "Legitimate".

  2. A second React frontend was built separately in frontend/ using Vite.
     Title: "PhishGuard AI"
     It also calls /predict via axios.post().
     Vite proxies /predict to Flask :5000.

  3. The React Home.jsx (frontend/src/pages/Home.jsx) determines result with:
       const bad = result?.prediction === 'Phishing';
     This is CORRECT logic -- reads data.prediction from the Flask JSON.

  4. However, useHistory hook (frontend/src/hooks/useHistory.js) persists
     every result to localStorage key 'phishing-history'.
     If a previous request returned "Phishing" (e.g., when kongu.ac.in
     was temporarily DNS-failing), that result is cached and visible
     in the History view, potentially being confused for a new result.

  5. Most likely explanation: The user was viewing the Vite UI at :5173
     ("PhishGuard AI") while all Flask instrumentation was printing to
     the Flask UI at :5000. The two UIs are completely independent.
     The trace logs confirmed the Flask backend was correct but the
     wrong frontend window was being observed.
