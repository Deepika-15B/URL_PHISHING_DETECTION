5. KONGU ROOT CAUSE
======================================================================
Root cause: extract_metadata_dom_features() in utils/html_feature_extractor.py
already used tldextract for brand_name extraction, but extract_form_features()
and extract_link_features() still used naive parts[-2] splitting for
page_domain. These gave incorrect page_domain = "ac.in" instead of
"kongu.ac.in" for the link/form external-domain checks.

More critically: the title-domain similarity (URLSimilarityIndex /
DomainTitleMatchScore) depended ENTIRELY on brand_name from
extract_metadata_dom_features(), which correctly extracted "kongu"
via tldextract. So the title-matching code was correct.

The REAL root cause of the 40-score was an EARLIER version of the code
that used parts[-2] instead of tldextract for brand extraction.
The historical bug produced URLSimilarityIndex=40, DomainTitleMatchScore=40.
The current code (with tldextract in extract_metadata_dom_features)
already produces the correct score of 100.0, giving Legitimate.

However, extract_form_features and extract_link_features still used
naive parts[-2] for page_domain comparison. For www.kongu.ac.in:
  naive: page_domain = "ac.in"   (incorrect - classifies kongu.ac.in links as external)
  fixed: page_domain = "kongu.ac.in" (correct via tldextract)
This was causing incorrect NoOfExternalRef / NoOfSelfRef counts for
multi-part TLD domains.

======================================================================

JavaScript challenge page to block headless browser automation.

BEFORE FIX:
  is_anti_bot() did NOT check for AWS WAF markers.
  The navigation succeeded via domcontentloaded fallback but
  returned only the 2006-byte challenge stub.
  page.title() = "" (empty)
  The system then fell into the "empty title + low DOM" interstitial
  guard at lines 700-745 in predict.py, which returned Unknown.
  This was correct behavior, but the error path was the generic
  "PARTIAL_EXTRACTION" rather than the explicit "BOT_PROTECTION_PAGE"
  AntiBotProtectionError path.

AFTER FIX:
  is_anti_bot() now detects AWS WAF markers:
    "awswaf", "awswafcookiedomainlist", "token.awswaf.com",
    "challenge-container", "verify that you're not a robot", "aws waf"
  After 8-second wait (challenge still not resolved), raises:
    AntiBotProtectionError("Cloudflare/Anti-bot challenge detected.")
  predict.py catches AntiBotProtectionError and returns:
    status      = BOT_PROTECTION_PAGE
    prediction  = Unknown
    confidence  = 0
    threat_score= 0
    risk_level  = Unknown
    reason      = "Website is protected by anti-bot mechanisms."
